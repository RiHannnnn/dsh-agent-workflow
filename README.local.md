# Agent 工作流 · Codex 本地开发版

> 基于 CodermanYHZ/dsh-node-flow 的本地扩展。保留原项目 MIT 许可证。当前交付是可构建、可测试的开发副本，尚未安装进正在运行的 DSH，也没有启动替代 Web 服务。

## 能做什么

- 在 DSH 原生主面板贡献「Agent 工作流」入口，不替换应用根节点，不挂独立 iframe，也不手工插入侧边栏 DOM。
- 从 `CODEX_HOME/agents`（默认用户 Codex 主目录下的 agents）发现 TOML 角色；显示名称、描述和搜索结果，支持点击加入及拖拽到画布。
- Codex 是执行引擎，Agency Agents TOML 的 `developer_instructions` 是角色指令；角色指令传入 Codex 的 developerInstructions，而资料进入 user 输入。不是为每个角色安装另一套模型。
- 输入节点可填写文本、嵌入多份文本附件。附件全部 UTF-8 内容合计不超过 1 MiB，仅支持文本/Markdown/JSON/CSV 等明确文本类型；PDF、Office、图片与二进制不在本版范围。
- 普通无环图支持串行、并行、完整输入汇合；节点显示实时文字，右侧可查看当前输入、输出、日志和错误。
- Codex 使用 app-server stdio JSONRPC 的真实增量事件，经同源 NDJSON 路由送到浏览器。不是用定时器伪造逐字打印，也不把 JSONL 日志等同于 token 流。
- Codex 节点可选「完整交接」或「逐段交接」。后者以空行分隔段落，在上游完成前把已形成的段交给下游。
- 手动运行支持停止；离开面板会取消本面板运行。工作流可导入/导出；导出不含每次运行的输入快照、日志和输出，嵌入附件本身仍在工作流中，分享前请检查。

## 第一次使用（需要先获批安装启用）

1. 将此项目通过 DSH 宿主的本地 bundle 安装入口加入当前 desktop 配置。不要直接修改应用安装包或手写 profile 配置，也不要另开 Vite 页面代替当前 DSH。启用时不自动恢复旧定时任务，不发起模型调用；原版定时器仅在用户主动保存/清除计划后启动。
2. 根据安装结果判断是否已应用、是否需要刷新或重启；不能以「构建成功」推断当前页面已经加载新代码。
3. 在侧边栏打开「Agent 工作流」→「添加节点」→「Codex 角色库」。
4. 拖入一个输入节点、两个 Codex 角色和一个输出节点，再连线。
5. 为每个 Codex 节点填写已存在的绝对工作目录并确认。模型留空沿用本机 Codex 默认配置。
6. 上游任务中要求“每个条目单独一段，段落之间留空行”，并将交接设为逐段；下游设定每一段的处理任务。
7. 点击运行，核对目录、模型服务发送提示、逐段调用次数和代码节点风险后确认。
8. 点击节点查看实时结果。需要取消时点击停止；检查后台子进程是否结束。

仓库附带不含本机绝对目录的示例。导入不会自动执行，必须先填写工作目录并主动运行。

## 逐段模式的准确含义和限制

- 每个输入段会触发下游一次独立调用，不共享会话记忆，不假定下游能看到整篇资料。
- 下游若使用完整交接，会等其所有独立调用结束，再把合并结果交给下一节点。
- 普通图最多 64 个执行节点、128 条边；并发最多 2 个执行任务，每次运行最多 32 次 Agent 调用。
- 每条增量边最多排队 32 段。超出后停止并提示，不无限积压。它是有界队列，不是无限吞吐的消息中间件。
- 每段 UTF-8 最大 64 KiB；节点结果及 Codex 请求提示最大 2 MiB，HTTP 请求体最大 4 MiB。
- 逐段节点暂不支持直接进入多路汇合；需先通过完整交接节点聚合。Codex 也暂不接 If/Switch/Loop/While 或定时任务。
- 已交付下游的段不能回滚。选择“失败后继续”时，会在保留已交付段的基础上再交付一次空输入；需要严格原子性时请使用完整交接。
- 普通图中任何不可继续的节点错误会停止本次图。原版控制流仍采用原版完整交接行为，不能把两种调度语义混为一谈。
- 运行时禁止替换整个工作流，避免旧运行输出写入新图；正在运行的配置来自启动时快照。编辑供下一次运行使用。

## 权限与隐私

- Codex 固定 `read-only` 文件沙箱、`approvalPolicy: never`，不使用危险绕过选项。启动后若返回更宽松策略，会在提交 turn 前拒绝继续。
- 只读不等于只可读取所选目录。不要对含敏感资料的目录运行不可信角色或提示词；资料标记不是完整的提示注入防线。
- 运行前关闭 hooks、plugins、apps、多 Agent 功能、web search、notify 和登录 shell。运行时仅为收集 MCP 名称读取普通本地 TOML 配置，并逐一禁用；不把配置值、认证内容或角色指令返回角色库界面。
- 发现托管配置、无法确定的配置来源、畸形文件或不安全链接时拒绝运行。需要隔离配置时应由用户另行配置和登录隔离的 Codex 主目录，插件不复制认证文件。
- 配置探测与 Codex 读取之间仍存在外部修改窗口。不要在运行时更改 Codex 配置；本版不宣称对恶意同用户进程提供隔离。
- 新增路由限制为严格同源的 loopback 地址；执行还需回送每次插件加载随机生成的 capability。它是本地防跨站触发措施，不是多用户认证系统，也不能防同源恶意插件。不要将此开发插件作为公网服务暴露。
- 原项目的代码节点和表达式可以执行用户代码，不享有 Codex 的只读保证。仅运行你信任的工作流；运行确认会显示这类节点的风险。
- 点击运行会使用本地 Codex 已配置的服务，可能产生费用并向该服务发送资料。本地角色库扫描、构建与 mock 测试不会调用模型。

## 开发和验证

使用 Node 22+、pnpm。项目依赖已经在开发副本安装；首次重新安装时建议禁用依赖脚本并检查锁文件。

```sh
pnpm install --ignore-scripts
pnpm run typecheck
pnpm run build
pnpm run test
```

默认 build 仅构建 DSH 原生插件。原项目的独立演示页面保留为可选 build:demo；本环境尝试构建该演示时，Rollup 原生扩展被 macOS 的签名 Team ID 检查拒绝加载。没有移除系统校验或修改签名；这个可选演示不属于当前 GUI 插件交付，也没有启动它。

自动测试覆盖：TOML 角色元数据、目录/链接校验、权限与 origin/capability 校验、JSONRPC 增量事件、畸形协议、取消/超时/卸载、DAG 汇合、上游未结束时启动下游、UTF-8 分帧、流意外中断、导入校验及输出日志剔除。测试使用 synthetic 配置、模拟 transport 和 mock 子进程；不以测试替代真实模型与 GUI 验证。

仍需在安装获批后验证：当前 DSH 的实际入口与样式、原有插件共存、Codex 登录/模型配置、真实模型实时输出和两个角色的端到端交接。没有真实页面截图或运行证据前，不宣称“已在你的 DSH 中可用”。
